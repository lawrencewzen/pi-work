# Grok 登录

设置 → 模型。使用操作者自己的 Grok Build 账号。不要把用户码、访问令牌或 API Key 写进记录。

## GK-1 从未登录进入设备码

### 步骤

1. 若已经登录，在来源「Grok 订阅」的编辑里点「退出登录」，或删掉这条 Grok 来源。
2. 打开设置 → 模型，点「＋ 添加来源」，再点「Grok Build」。

### 预期

- 右侧抽屉标题是「登录 Grok Build」。
- 能看到授权网址和「打开」，用户码和「复制」，以及过期倒计时。
- 有等待说明，和「取消」。
- 页面上没有单独的 Base URL / API Key 主输入框。

## GK-2 设备码登录成功

### 步骤

1. 按抽屉里的链接和用户码在浏览器里确认。
2. 等待页面自己完成，不要手动粘贴令牌。

### 预期

- 成功后抽屉关闭，来源列表里出现 Grok 来源，状态为可用。
- 行内是账号和令牌续期说明，不是一份明文令牌。
- 刷新后仍是已登录。

## GK-3 不填 API Key 也能对话

### 步骤

1. 保持 GK-2 的登录。不要另加 API 来源。
2. 给默认角色选这个 Grok 来源的模型并保存。若还没选，芯片也会用该来源的第一个模型。
3. 新建对话，发送 `用一句话回答：1+1 等于几？`，等到完成。

### 预期

- 有一条助手回复，内容承认结果是 2。
- 状态变为完成，不出现要求填写 API Key 的错误。

## GK-4 退出只清会话

### 步骤

1. 在 Grok 来源的编辑里点「退出登录」。

### 预期

- 这条来源变为不可用，原因是未登录。已有的 API 来源还在，它们的 Key 不被清掉。
- 刷新后仍然是未登录。
- 编辑里还可以「换个账号重新登录」。删除这条来源会同时退出登录。
