# Grok 登录

设置 → 模型。使用操作者自己的 Grok Build 账号。不要把用户码、访问令牌或 API Key 写进记录。

## GK-1 未登录时的入口

### 步骤

1. 若当前已登录，先点「退出登录」，确认回到未登录。
2. 打开设置 → 模型。

### 预期

- 卡片标题是「用 Grok 登录」，说明是使用 Grok Build 订阅、不必填写 API Key。
- 有按钮「用 Grok 登录」。
- API Key 区域可见，作为没有会话时的回退。

## GK-2 设备码登录

### 步骤

1. 点击「用 Grok 登录」。
2. 按页面给出的链接和用户码在浏览器里确认。
3. 等待页面自己完成，不要手动粘贴令牌。

### 预期

- 等待期间能看到链接、用户码和「等待确认…」。
- 成功后卡片变为「已用 Grok 登录」，并出现「退出登录」。
- 提示当前对话走 Grok 订阅代理。API Key 收进「API Key（可选回退）」，不再是主输入。
- 刷新后仍是已登录。

## GK-3 不填 API Key 也能对话

### 步骤

1. 保持 GK-2 的登录，不要在密钥框里输入新 Key。
2. 新建对话，发送 `用一句话回答：1+1 等于几？`
3. 等到完成。

### 预期

- 有一条助手回复，内容承认结果是 2。
- 状态变为完成，不出现要求填写 API Key 的错误。

## GK-4 退出只清会话

### 步骤

1. 在模型页点击「退出登录」。

### 预期

- 卡片回到「用 Grok 登录」。
- 若之前没有保存 API Key，密钥框是空的回退输入，而不是一份被删掉的会话令牌。
- 刷新后仍然是未登录。

## GK-5 更换服务商或地址前的确认层

用一份可以丢掉的本地数据来做。不要把密钥写进记录。若这台机器上有需要保留的 API Key，先不要跑本条。

### 步骤

1. 打开设置 → 模型。API Key 填一个任意测试值，点「保存设置」。
2. 改 Base URL 或换一个服务商，不要在密钥框里输入新密钥，再点「保存设置」。
3. 在确认层点「取消」。
4. 语言选 English。回到模型，再改一次 Base URL 或服务商（切换语言会按已保存的值重绘，刚才没保存的修改不会留着），点保存。看确认层后点 Cancel。切回中文。
5. 再点「保存设置」，在确认层点「继续」。
6. 把 Base URL 和服务商改回原来的值并保存。密钥此时应已清空，不要再写入真实密钥。

### 预期

- 第 2 步出现页面内确认层，盖在设置之上，不是浏览器原生确认框。
- 中文标题是「请确认」。正文是「更改服务商或 Base URL 时若未输入新密钥，已保存的 API Key 将被清空以确保安全。是否继续？」。按钮是「取消」和「继续」。继续是主按钮，不是危险样式。
- 点「取消」后确认层关闭，设置还在，密钥框仍显示已保存的掩码。
- 英文标题是 `Please confirm`，正文是 `Changing provider or Base URL without entering a new key will clear the saved API key for safety. Continue?`，按钮是 Cancel 和 Continue。点 Cancel 不保存这次修改。
- 点「继续」后提示「设置已保存」，已保存的 API Key 被清空。
