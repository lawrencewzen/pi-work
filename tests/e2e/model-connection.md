# 模型连接

默认界面是中文。不要把用户码、访问令牌或 API Key 写进记录。

## MC-1 未连接模型时发送

没有任何可用模型来源：没有已登录的 Grok，也没有带 Key 的 API 来源。服务器不要带 `LLM_API=faux`、`WEFT_LLM=faux` 或 `WEFT_FAUX_SCRIPT` 启动。

### 步骤

1. 若当前已登录 Grok，在设置 → 模型里退出登录或删除 Grok 来源。若还有 API 来源，删掉。
2. 确认顶栏和作曲栏都没有「演示模型」。
3. 新建一条对话，发送 `你好`。

### 预期

- 对话里出现错误「未连接模型：请先在 设置 → 模型 登录 Grok」，同时有一条同样文字的 toast。
- 没有助手回复。回复里不能出现剧本句子（例如 `reported usage`）。
- 状态是「失败」，不是「完成」。这条发送不算成功运行。

## MC-2 登录后得到真实回复

需要操作者自己的 Grok Build 账号，或一个已经测通的 API 来源。登不上、也没有 API 来源时把本条记为阻塞，不要记为失败。

### 步骤

1. 仍不要设置 `LLM_API=faux` 或 `WEFT_FAUX_SCRIPT`。
2. 在设置 → 模型用「＋ 添加 → Grok Build」完成登录，或添加一个可用的 API 来源并给默认模型选上、保存。
3. 新建一条对话，发送 `用一句话回答：1+1 等于几？`，等到结束。

### 预期

- 有一条助手回复，内容承认结果是 2，不是固定剧本。
- 状态是「完成」。
- 顶栏和作曲栏都没有「演示模型」。

## MC-3 演示模式有徽章

用演示模型重新启动，例如 `LLM_API=faux npm start`，或 `WEFT_FAUX_SCRIPT=tests/fixtures/usage.json npm start`。

### 步骤

1. 打开工作台，先不要发送消息。
2. 看顶栏，再看作曲栏 Agent 芯片旁边。
3. 把界面切到英文，看同一位置，然后切回中文。

### 预期

- 中文时顶栏和 Agent 芯片旁都有「演示模型」。英文时是 `Demo model`。
- 徽章在发送前后都在，不能把它当成已登录的真实模型。
- 切回中文后仍是「演示模型」。
