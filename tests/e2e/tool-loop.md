# 工具连呼与单步上限

需要可用模型，以及一个可写的本地工作区。默认连续相同调用 3 次后会拦住。对同一个文件或同一个路径换着参数查看，超过 2 次也会拦住。本步已经调用了 8 次工具却还没有文字回复时，会提醒模型根据已有结果回答。每一步最多大约 15 次工具调用。

## TL-1 相同工具不会无限制重复

### 步骤

1. 新建对话，角色选「审计」。
2. 发送：`用 ls 看一下仓库根目录，然后用一句话说明看到了什么。不要对同一个目录反复调用 ls。`
3. 等到状态变为「完成」。数一数对话里 `ls` 工具行。

### 预期

- 状态是「完成」，不是一直停在「运行中」。
- 不会出现几十次参数相同的 `ls`。
- 若同一个工具带着相同参数连续出现了 3 次，紧接着能看到「停止调用工具」，并且后面有助手的文字回复，而不是继续空转。

## TL-2 换着参数翻找也会停

对应技能关掉时的「口令检查」：模型用不同参数反复 `ls` / `read` / `grep` / `bash`，既不是完全相同的调用，也还没到很高的次数。

### 步骤

1. 确认设置 → Skills 里没有启用名为「口令」的 Skill。没有这个 Skill 也可以。
2. 新建对话，角色用默认 Agent。
3. 发送：`口令检查`。如果模型很快用一句话答完，再发一条：`在仓库里查找和口令有关的文件。可以换目录、换关键词看，但看完用一两句话回答，不要一直翻。`
4. 等到状态变为「完成」。数一数这一步里的工具行。

### 预期

- 状态是「完成」，不是停在「运行中」。这一步的工具调用不会到二十多次。
- 若助手还没写文字、工具却已经有 8 次，对话里会出现「请根据已有结果直接回答」，后面有助手的文字，或说明还缺什么。
- 同一个文件的 `read`，或同一个路径上的 `ls` / `grep`（关键词、glob 可以不同），不会超过两次。超过时能看到「不要再重复查看」。用 bash 对同一个路径反复 `ls`、`grep` 或 `cat` 也一样。
- 若工具仍然很多，大约 15 次后出现「工具调用已达上限」，然后这一步结束。
