# 模型来源

设置 → 模型。不要把 API Key、令牌或用户码写进记录。需要两个本地假 OpenAI 兼容服务（都实现 `GET /v1/models` 和 `POST /v1/chat/completions`），各自返回不同的模型 id。不要用 faux 模式。

## MS-1 来源列表

### 步骤

1. 打开设置 → 模型。

### 预期

- 有「模型」和「默认模型」两块。默认模型只有一行，分区标题旁是「可用模型列表」，底部有保存条。
- 没有「角色模型」整块，没有服务商标签、Base URL、API Key 手输框，也没有按角色手填模型名的输入框。
- 默认模型是一个下拉按钮，不是原生 select。
- 设置导航里没有「Agent」页，也没有「流程」。

## MS-2 添加并测试两个 API 来源

### 步骤

1. 点「＋ 添加」。账号登录里除 Grok Build 外，ChatGPT（Codex）、GitHub Copilot、Claude 显示「即将支持」且点不了。
2. 点「添加 API」。选「自定义…」，地址填第一个假服务的 `/v1`，填一个测试 Key，名称填「甲」。点「测试并获取模型」，勾选它返回的模型，点「添加」。
3. 同样再加来源「乙」，指向第二个假服务。

### 预期

- 测试成功后列出模型，可以勾选，也可以手动补一个名字。
- 两条来源出现在列表里，状态点为可用，能看到打码后的 Key、主机和刚测试通过。
- 明文 Key 不出现在列表里。

## MS-3 默认模型下拉和保存条

### 步骤

1. 给默认模型选来源甲的模型。保存条出现未保存提示。
2. 点「放弃」，再重新选一次，点「保存」。
3. 刷新页面。

### 预期

- 改默认模型时保存条显示未保存，放弃后恢复。模型页只有默认模型一行。
- 保存后来源本身不用再点一次保存（来源在抽屉里已经生效）。
- 刷新后默认模型仍是刚才选的。
- 下拉按来源分组，可搜索。放不下时向上弹出，不被设置弹窗裁掉。

## MS-4 不可用来源置灰

### 步骤

1. 再加一个指向未启动地址的来源（或本地 Ollama，且本机没有 Ollama），点测试。
2. 打开默认模型下拉，看到这个来源。

### 预期

- 列表里该行状态点不可用，并写原因（连不上，或 Ollama 没启动一类的说明）。
- 下拉里这个来源整组置灰，点不了。

## MS-5 编辑时换主机必须重填 Key

### 步骤

1. 编辑来源甲，把厂商改成「自定义…」（或直接改地址），把主机改成另一个地址，Key 保持打码值，不要输入新 Key。
2. 点「保存」。

### 预期

- 保存前就提示需要重新填写 API Key。
- 抽屉不关闭。假服务和 Weft 都没有收到这次保存请求。
- 填一个新的测试 Key 后才能保存。

## MS-6 删除正在使用的来源

### 步骤

1. 把默认模型设为来源乙并保存。
2. 删除来源乙，并在确认层点删除。

### 预期

- 确认层是页面内的，不是浏览器原生确认框。
- 默认模型回到自动（下一个可用来源），刷新后仍是这样。

## MS-7 发消息打到对应来源

### 步骤

1. 模型页把默认模型设为来源甲并保存。
2. 新建对话，发送一句短消息，等完成。
3. 用作曲栏芯片把这条对话切到来源乙的模型，再发送一句，等完成。

### 预期

- 芯片显示的是模型名，不是手输的整段地址。
- 没有对话级覆盖时芯片显示默认模型。
- 第一句打到甲，请求里的模型是甲的模型。
- 第二句打到乙，请求里的模型是乙的模型。

## MS-8 英文没有漏翻

### 步骤

1. 设置 → 通用，语言改为 English。
2. 回到模型页，打开「＋ 添加」和默认模型下拉。
3. 改回中文。

### 预期

- 来源、默认模型、抽屉、保存条上的界面文字都是英文。
- 改回中文后恢复中文。
