# 上下文芯片

需要可用模型。用量只来自模型响应里的 token 计数，不估算。先有一个工作区和一条还没跑过的对话。

## CX-1 还没有用量

### 步骤

1. 打开这条新对话，不要发送消息。
2. 看作曲栏右下角的上下文芯片。

### 预期

- 显示 `已用 0% · 剩 100% · <上限>`（例如 `128k`）。上限取当前模型在设置里的值，没有则用该来源的默认（128k）。
- 不再显示 `—`，也不再带「上下文」文字标签。

## CX-2 一轮模型结束后出现用量

### 步骤

1. 在同一条对话里发送一句短指令，例如 `用一句话回答：你好`。
2. 等到状态变成完成。
3. 再看上下文芯片。
4. 刷新页面。

### 预期

- 完成后芯片变成「已用 x% · 剩 y% · 上限」，x + y = 100，百分比四舍五入。左边小圆环按已用比例填充；已用 ≥ 80% 时圆环变成警告色。
- `title` 为「上下文 已用token / 上限 · 已用 x% · 剩余 y%」。
- 刷新后数字还在。
- 若这次响应没有带任何 token 字段，芯片保持 `已用 0% · 剩 100% · 上限`，不要记成失败；把该条记为阻塞并注明模型没有返回用量。

## CX-3 点芯片选上限

### 步骤

1. 点上下文芯片。
2. 在菜单里选一档（例如 `256k`）。

### 预期

- 菜单标题是「<模型名> · 设置上下文上限」，上面两行是已用 / 剩余（不可点），下面是档位，当前档带 ✓。
- 点档位后发出 `PUT /api/sources/:id`，body 为 `{ contextWindows: { "<模型名>": 256000 } }`（真后端，不 mock）。
- 芯片立刻按新上限重算。设置 → 模型页的「上下文上限」同步为同一值。
- 刷新页面后芯片仍显示该上限（例如 `已用 6% · 剩 94% · 256k`）。`GET /settings` 的 `sources[].contextWindows` 含该值。
- 没有可用模型时芯片不可点。
