# 上下文芯片

需要可用模型，并且这次模型调用会在响应里带上 token 用量。先有一个工作区和一条还没跑过的对话。

## CX-1 还没有用量

### 步骤

1. 打开这条新对话，不要发送消息。
2. 看作曲栏里「上下文」后面的数字。

### 预期

- 显示 `上下文: —`。
- 没有编造出 `k` 或窗口数字。

## CX-2 一轮模型结束后出现用量

### 步骤

1. 在同一条对话里发送一句短指令，例如 `用一句话回答：你好`。
2. 等到状态变成完成。
3. 再看「上下文」芯片。
4. 刷新页面。

### 预期

- 完成后芯片从 `—` 变成「已用 / 窗口」，例如 `1.2k / 128k` 或 `16.4k / 200k`。数字来自模型响应里的 token 计数，窗口来自该响应里的上下文窗口，没有则用配置 `LLM_CONTEXT_WINDOW`（默认 128000）。
- 刷新后数字还在。
- 若这次响应没有带任何 token 字段，芯片保持 `—`，不要记成失败；把该条记为阻塞并注明模型没有返回用量。

## CX-3 只保留最近一次

### 步骤

1. 在已经出现用量的对话里再发送一句短指令。
2. 等到完成。

### 预期

- 芯片显示的是最近这一次调用的用量，不是两次相加后的总数。
- 模型没再返回用量时，芯片保持上一轮的数字，不改成 `—`，也不估算。
